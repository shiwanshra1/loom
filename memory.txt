**Bug caught and fixed before it shipped:** first draft of the router wired all 9 roles through a `<RoleSection>` wrapper *component* — react-router v6's `<Routes>` extracts its config by statically walking the JSX tree for literal `<Route>`/`<Fragment>` elements, so wrapping `<Route>` in another component breaks that traversal (it only tolerates Fragments, not arbitrary components, as pass-through). Fixed by making `roleSection` a plain function that returns a `<Route>` element directly instead of a JSX component — no headless browser available this session to catch this at runtime, so this was caught by reasoning through react-router's actual `createRoutesFromChildren` source rather than by testing; verification was typecheck+lint+build+curl smoke-test as before.
